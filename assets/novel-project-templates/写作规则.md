# 写作规则

> 本文件是每次写作的执行铁律。Agent 写每一章之前必须读取并遵守，作者确认后生效。

## 一、八条铁律

1. **正式正文已经发生的事实，优先级最高。** 任何大纲、设定与正文冲突时，以正文为准。
2. **每次写前，必须读取本章所需资料。** 至少包括：本规则、当前滚动细纲、上一章正文、出场人物卡、开放伏笔清单。
3. **资料没有的核心设定，不得擅自补全。** 发现缺失先停下，向作者提问，不得编造。
4. **人物按自己的目标、利益和已知信息行动。** 人物只知道他应该知道的事，不共享上帝视角。
5. **不靠集体降智、越权或凭空资源推进剧情。** 每个决定都要有权限、有资源、有动机。
6. **每个场景至少改变一项信息、关系或风险。** 不产出变化的场景不写或合并。
7. **章尾必须形成一个具体的不可逆的新局面。** 不用「欲知后事如何」糊弄。
8. **冷读通过后，必须回写人物、伏笔和时间线。** 不回写不算完成。

## 二、每章八步循环

以后每一章，都严格执行同一循环，顺序不可颠倒：

| 步骤 | 名称 | 做什么 |
|---|---|---|
| 01 LOAD | 读取资料 | 规则、细纲、上一章、人物和开放伏笔 |
| 02 CHECK | 写前检查 | 检查冲突、缺失、时间、资源和权限 |
| 03 CONTRACT | 章节合同 | 明确目标、阻力、主场面和章尾（见 审核与复盘/章节合同-模板.md） |
| 04 DRAFT | 写初稿 | 按场景写，不把细纲逐条扩句 |
| 05 REVIEW | 读者冷读 | 只看正文，不替作者脑补 |
| 06 REVISE | 修改问题 | S1、S2 没有清零，不标记完成 |
| 07 UPDATE | 回写数据库 | 同步时间、人物、伏笔和资源变化 |
| 08 DECIDE | 人做判断 | 这一章到底好不好看，由作者裁决 |

## 三、冷读检查项（REVIEW 步骤用）

- 这是谁？为什么现在这样做？
- 他凭什么决定？资源从哪来？
- 人物有没有失忆、越权或写偏？
- 场景、位置和动作能否看见？
- 哪里会让读者想跳读？
- 章尾会不会让人马上追？

## 四、回写清单（UPDATE 步骤用）

- 结束的绝对时间 → `追踪/时间线.md`
- 人物位置、状态和新信息 → `追踪/角色状态.md`
- 关系与目标变化 → `人物/人物关系.md`
- 伏笔新增、推进和回收 → `追踪/伏笔.md`
- 金钱、物品和权限变化 → `追踪/资源与权限.md`
- 下一章必须读取的资料 → `00-项目状态.md` 的「本次必读」

## 五、问题分级

| 级别 | 定义 | 处理要求 |
|---|---|---|
| S1 | 设定、动机、主线或现实逻辑错误 | 必须清零 |
| S2 | 明显损害节奏、读感和追读 | 必须清零 |
| S3 | 局部表达问题 | 交稿前尽量清零 |

## 六、退回机制

- 章节合同中任何一问只能回答「为了推进剧情」→ 停止写正文，退回细纲。
- 冷读发现 S1/S2 未清零 → 稿件放入 `待确认/`，不得转入 `正文/`。
